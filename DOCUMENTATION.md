## 1. Что это за проект

**DRX** — автоматический торговый робот для **мемкоинов на Solana DEX**. Он сам сканирует новые токены (DexScreener), анализирует график (GeckoTerminal OHLCV), принимает решения по стратегиям, покупает через **Jupiter** (или виртуально в DEMO), сопровождает позицию (SL/TP/trailing) и считает статистику.

### Что бот умеет

- **Сканировать новые мемкоины** — DexScreener boosts/profiles + фильтры (ликвидность, MC, возраст).
- **Торговать на DEX** — свопы SOL→token→SOL через Jupiter Aggregator (REAL) или paper-trading (DEMO, счёт $10 000).
- **Запускать до 3 стратегий параллельно** — каждая со своими фильтрами и параметрами выхода.
- **Сопровождать позиции** — Stop Loss, Take Profit, частичные фиксации, trailing, break-even, time-stop и **ликвидность-стоп** (защита от rug pull).
- **Управлять рисками** — лимит дневного убытка, максимальная просадка, лимит позиций.
- **Управление через Telegram** — старт/стоп/пауза, баланс, позиции, статистика, стратегии, сканер, режим DEMO/REAL.
- **REST API + WebSocket** — для интеграции с UI и внешними системами.
- **Desktop/Android-дашборд (Compose Multiplatform)** — equity-кривая, история, аналитика, редактор стратегий.
- **SQLite-хранилище** — стратегии, сделки, кеши, настройки.

### Где бот живёт

Бот построен как **сервер на JVM**. Его можно запускать:
- локально на ПК (Windows / macOS / Linux) — `start.bat` / `./gradlew :server:run`;
- на VPS (рекомендуется) — чтобы работал 24/7;
- внутри Desktop-приложения (движок встроен в UI — для тестов).

## 2. Архитектура проекта

Gradle-мультимодульный Kotlin Multiplatform (структура MRX):

```
SolTradBott/
├── shared/         ← Общая бизнес-логика + Compose UI (KMP: JVM + Android)
├── server/         ← Ktor HTTP-сервер на JVM (порт 8080) — главный торговый процесс
├── desktopApp/     ← Compose Desktop UI (Windows/macOS/Linux)
├── androidApp/     ← Android-приложение
├── gradle/         ← Версии зависимостей (libs.versions.toml)
└── setup.bat / start.bat / desktop.bat / Dockerfile / docker-compose.yml
```

## 3. Торговые стратегии

При первом запуске бот создаёт в БД **5 стратегий** (`SeedData.kt`): Dars (включена), «Пробой + откат», «Мем-плейбук», «Волны Эллиотта» и «Пробой на объёме». «Вход по баллу» создаётся вручную в форме.
Стратегии Momentum Scalping и RSI + EMA удалены; их записи из старой БД убираются при запуске.
В уже существующую БД «Пробой + откат», «Мем-плейбук», «Волны Эллиотта» и «Пробой на объёме» добавляются один раз при обновлении (удалённые пользователем — не возвращаются).

### 3.1 Dars / Smart Money — сканер мемкоинов *(включена по умолчанию)*

Основная стратегия по торговому курсу «Dars», адаптированная под мемкоины:
- тренд старшего ТФ (15m) + уровни (крупный бар, разворотная точка, зеркальный);
- сетапы: импульс/коррекция (Урок 1), ложный пробой (Урок 3), треугольник (Урок 5);
- «не покупаем у сопротивления» (Урок 4);
- вход только в LONG (бот спотовый).

| Параметр | Значение |
|----------|----------|
| Таймфрейм | 1m (тренд — 15m) |
| Размер позиции | 5% от баланса |
| Stop Loss | 15% |
| Take Profit | 30% (RR ≈ 2) |
| Фильтры | LIQ ≥ $10K, MC $50K–$10M, возраст 30м–30д, объём 1ч ≥ $5K |

### 3.2 Пробой + откат — мемкоины с историей

Связка Momentum → Pullback → Volume confirmation (обоснование — `STRATEGY_RESEARCH.md`). Пробой не покупается — он «взводит» сетап, вход на откате:
1. **Пробой**: закрытие выше максимума 20 баров на объёме ≥ 2× среднего, закрытие в верхней части бара.
2. **Откат**: ≥ 2 баров после пика, минимум удержал уровень пробоя (допуск 0.5 ATR), средний объём ≤ 70% объёма импульса, без всплеска продаж.
3. **Триггер**: бычий бар выше максимума предыдущего, закрытие ≥ 60% диапазона, объём ≥ 1.2× среднего объёма отката.
4. **Стоп** под минимумом отката − 0.5 ATR. Отказ, если стоп дальше SL% (12%) или до пика импульса < 1R.
5. **Тренд 15m** восходящий (нет данных — нет входа).

| Параметр | Значение |
|----------|----------|
| Таймфрейм | 5m (тренд — 15m) |
| Размер позиции | от риска: 1% баланса на стоп, не больше 10% баланса и 1% ликвидности пула |
| Выходы | TP1 40% на +1.5R → безубыток +2%, TP2 30% на +3R, остаток 30% — раннер под ATR-трейлингом (3×ATR от пика) |
| Time-stop | 120 мин, только пока TP1 не взят |
| Фильтры | LIQ ≥ $20K, MC $100K–$20M, возраст 3ч–30д |

### 3.3 Мем-плейбук — откат по Фибоначчи, «тело» на 2x

Связка из обзора исследований мемкоинов (`STRATEGY_RESEARCH.md` §8): отсечь мусор → не покупать памп → вход на откате → размер от риска → выходы «по иксам».
1. **Фильтр монеты**: ликвидность ≥ 3% капитализации, возраст ≥ 60 мин (фильтр сканера).
2. **Импульс**: от минимума до максимума окна (72 бара) ≥ +50%.
3. **Откат** на 0.382–0.786 импульса на затухающем объёме (≤ 70% импульса), без всплеска продаж. Глубже 0.786 — «пустой памп», вход не делается.
4. **Триггер**: бычий бар выше максимума предыдущего, закрытие ≥ 60% диапазона, объём ≥ 1.2× отката.
5. **Стоп** под минимумом отката − 0.5 ATR, но не глубже уровня 0.786. Отказ, если стоп дальше SL% (25%) или до максимума импульса < 1R.
6. **On-chain проверки** (только для найденного сетапа): mint и freeze authority отозваны (RPC `getAccountInfo`), монета — не копия более старой с тем же тикером (поиск DexScreener). Нет ответа сети — нет входа.

| Параметр | Значение |
|----------|----------|
| Таймфрейм | 5m |
| Размер позиции | от риска: 2% баланса на стоп, не больше 10% баланса и 1% ликвидности пула |
| Выходы | 50% на 2x («вернуть тело») → безубыток +2%, 25% на 3x, остаток 25% — под ступенчатым трейлингом (40% / 30% / 20% / 15% от пика до 2x / 2–5x / 5–10x / от 10x) |
| «Нет нового максимума» | через 4 ч трейлинг −10 п.п., через 12 ч — ещё −10, через 24 ч — выход |
| Ликвидность-стоп | −20% пула |
| Фильтры | LIQ ≥ $10K, MC $50K–$20M, возраст 1ч–30д |

### 3.4 Волны Эллиотта — вход в 3-ю и 5-ю волну

Порт стратегии `ElliottStrategy` из MRX (Frost & Prechter, «Elliott Wave Principle»), только покупка.
1. **Разметка**: разворот — отход от экстремума на 2.5 × ATR (меньше — волны младшей степени). Только по закрытым свечам: формирующийся бар GeckoTerminal отбрасывается.
2. **Правила книги** (нарушено одно — сделки нет): волна 2 не за началом 1-й, 3-я дальше конца 1-й и не самая короткая, 4-я не заходит на 1-ю, 5-я дальше конца 3-й.
3. **Строение**: движущие волны делятся на 5, коррекции — на 3 (проверка на младшей степени, 0.382 × порога; режимы «строго» / «не делится — допускаем» / «не проверять»).
4. **Ориентиры** (нужно ≥ 2 из применимых): откат 2-й 0.382–0.786 и 4-й 0.236–0.5, объём (2-я тише 1-й, 3-я громче), чередование 2-й и 4-й, канал, зона 4-й волны младшей степени.
5. **Вход**: в 3-ю — на первом закрытии за концом волны 1 (или, по выбору, на подтверждённом конце 2-й), в 5-ю — на подтверждённом конце 4-й; не позже 3 баров после повода. Отскок после нисходящей пятёрки — выключен по умолчанию.
6. **Стоп** — там, где счёт ломается по правилу (за началом 3-й при входе на пробое, за концом 1-й у 5-й) + 0.2 ATR. **Цель** — 1.618 × волны 1 для 3-й, 1 × волны 1 для 5-й. Нужно R:R ≥ 1.5, стоп не дальше Stop Loss (25%).
7. **Старшая степень** (выключено по умолчанию): текущая волна 1h должна идти вверх; свечи запрашиваются только для готового сетапа, нет ответа — нет входа.

| Параметр | Значение |
|----------|----------|
| Таймфрейм | 15m (старшая степень — 1h, выключена) |
| Размер позиции | от риска: 1% баланса на стоп, не больше 10% баланса и 1% ликвидности пула |
| Stop Loss / Take Profit | из разметки волн; Stop Loss 25% — только потолок расстояния до стопа, Take Profit в % не используется |
| Фильтры | LIQ ≥ $10K, MC $50K–$10M, возраст 12ч–30д (разбору нужно ≥ 44 закрытых свечей) |

### 3.5 Пробой на объёме — первый откат и пробой максимума

Сетап из треда о мемкоинах: «First pull back → Retesting previous high → Breaking previous high + Volume spike».
В отличие от «Пробоя + отката» вход — **на самом пробое**, а не на откате после него.
1. **Импульс**: от минимума окна (60 баров) до максимума ≥ +20%.
2. **Первый откат** от максимума ≥ 5%, но не глубже 0.786 импульса — минимум отката выше начала импульса.
3. **Ретест**: два бара перед пробоем закрылись не ниже чем на 8% под максимумом — цена «подползла» к уровню, а не выстрелила со дна отката.
4. **Пробой**: закрытый бар закрылся выше максимума, бычий, в верхней половине диапазона, на объёме ≥ 2.5× среднего за 20 предыдущих баров. Только закрытые свечи — пробой фитилём внутри формирующегося бара не считается. Пробой баром раньше ещё годится, если цена удержалась над максимумом.
5. **Не догоняем**: цена выше максимума больше чем на 15% — пропуск; цена входа — закрытие бара пробоя, и разбег живой цены с ней больше 3% тоже отменяет вход.
6. **Стоп** под базой (минимум трёх баров перед пробоем) − 0.25 ATR. Отказ, если стоп дальше SL% (15%).

| Параметр | Значение |
|----------|----------|
| Таймфрейм | 1m — сетап первых часов монеты: на 5m к моменту пробоя мало баров, а вход запаздывал бы на свечу |
| Размер позиции | от риска: 1% баланса на стоп, не больше 10% баланса и 1% ликвидности пула |
| Выходы | 30% на +2R → безубыток +2%, 30% на +4R, остаток — под ступенчатым трейлингом «по иксам» (40% / 30% / 20% / 15% от пика) |
| Time-stop | 60 мин, только пока TP1 не взят: пробой должен сработать быстро |
| «Нет нового максимума» | через 20 мин трейлинг −10 п.п., через 60 мин — ещё −10, через 2 ч — выход |
| Ликвидность-стоп | −30% пула |
| Фильтры | LIQ ≥ $15K, MC $50K–$10M, возраст 20 мин–12 ч |

> Выход важнее входа: после таких пробоев пампы часто откатываются целиком (на графике из треда цена вернулась к уровню пробоя после ×9). Сканер берёт монеты из профилей и бустов DexScreener, поэтому самые молодые монеты без платного профиля стратегия пока не видит.

> Бэктест (🧪): трендовые и топовые монеты старше 12 ч, а у «Новых» почти нет истории, поэтому с фильтром возраста 20 мин–12 ч бэктест покажет 0 сделок. Чтобы проверить сам паттерн, на время поднимите «Макс. возраст токена, мин» (например, до 10080 — неделя; при необходимости и «Макс. Market Cap») и включите «Одна сделка на монету (как в боте)»: без неё бэктест входит в монету повторно, а бот — нет.

> Все параметры каждой стратегии редактируются в UI (вкладка «Стратегии» → ✏️) или прямо в БД.

### 3.6 Бэктест стратегии (🧪)

Вкладка «Стратегии» → 🧪 на карточке. Бот прогоняет стратегию с её текущими параметрами по истории свечей GeckoTerminal (`domain/backtest`):
- **Монеты:** трендовые / новые / топ по объёму (5–50 штук), история 3–30 дней. Трендовые и топовые — это выжившие, результат будет лучше реального; «Новые» честнее.
- **Вход и выходы — те же, что у бота:** стратегия видит только закрытые свечи, вход по открытию следующей свечи; выходы считает та же функция `decideExit`, что и `TradeMonitor`.
- **Издержки:** задаются в % на вход и на каждый выход (по умолчанию 1%). На узких стопах они заметно ухудшают R.
- **Итог:** число сделок, winrate, ожидание в R на сделку, profit factor, сумма R, счёт и просадка при риске 1% на сделку, причины выхода, список сделок.
- **Загрузка:** лимит GeckoTerminal ~30 запросов в минуту, поэтому первая загрузка занимает минуты. Дальше история хранится в памяти: после правки параметров («✏️ Параметры» → сохранить) прогон на тех же данных мгновенный.
- **Не моделируется:** ликвидность-стоп, лимит позиций, кулдаун, on-chain проверки «Мем-плейбука» (authority, копикаты — монета считается чистой). Капитализация и ликвидность в прошлом оцениваются от текущих.

Меньше 30 сделок — статистика ненадёжна. Проверяйте параметры на другом периоде и на «Новых» монетах, чтобы не подогнать их под одну выборку.

## 4. Режимы DEMO / REAL / «только сигнал»

| Режим | Что происходит | Как включить |
|-------|----------------|--------------|
| **DEMO** (по умолчанию) | Сделки виртуальные, счёт $10 000, PnL считается по реальным ценам DexScreener. | `DEMO_MODE=true`, Настройки → «Режим DEMO», Telegram `/mode` |
| **SHADOW** (DEMO по котировкам) | Тот же виртуальный счёт, но сколько потрачено и получено — по настоящим котировкам Jupiter на ваш размер: комиссии пулов и проскальзывание видны в PnL, монету без маршрута продажи не продать и здесь. Транзакции не отправляются. | Настройки → «SHADOW» (при включённом DEMO), Telegram `/mode` → «Включить SHADOW», REST `POST /mode/shadow` |
| **REAL** | Реальные свопы через Jupiter с вашего кошелька (нужна seed-фраза). | Настройки → выключить DEMO, Telegram `/mode` |
| **Только сигнал** | Сделки не открываются вообще — бот шлёт алерт с параметрами входа (цена, SL, TP, mint). | Настройки → «Только сигнал», Telegram `/signalonly` |

**Рекомендация: минимум 1–2 недели на DEMO в режиме SHADOW**, потом REAL с маленьким размером позиции.
Обычный DEMO покупает и продаёт по цене графика без издержек, поэтому его результат лучше реального.

Переключатели хранятся в БД и применяются мгновенно — перезапуск не нужен. Режим каждой сделки
записан в `trade.exec_mode` (DEMO / SHADOW / REAL): сделка SHADOW и закрывается по котировке, даже если
переключатель потом выключили. Сетевые комиссии Solana и рента токен-аккаунта (~0.002 SOL) пока не
учитываются ни в SHADOW, ни в PnL REAL-сделок.

## 5. Вход и выход из позиции

### Вход (pipeline)

1. `TokenScanner` раз в ~30с отдаёт кандидатов (DexScreener → фильтры стратегии → скоринг). Кеш TTL 5 минут.
   Монеты, по которым уже была сделка или REAL-покупка ещё «в полёте» (журнал транзакций), пропускаются.
2. Стратегия анализирует свечи GeckoTerminal → сигнал BUY + уверенность (нужно ≥ 60%).
3. `RiskManager.canTrade()` — дневной убыток, просадка, лимит позиций стратегии; затем **лимиты портфеля**
   (все стратегии вместе, см. §11) — вход занимает «слот» под общим локом, чтобы две стратегии не вошли в один.
4. Размер: `balance × positionSize%`; с тумблером «Размер от риска» — `balance × риск% / расстояние до стопа`, но не больше `positionSize%` и доли ликвидности пула.
5. **Проверка монеты** (`EntryGuard`, для всех стратегий и режимов): mint/freeze authority отозваны, нет опасных
   расширений Token-2022, котировка Jupiter на этот размер — влияние на цену ≤ лимита, котировка обратной продажи
   есть и потери «купить и сразу продать» ≤ лимита. Нет данных (RPC, сеть, лимит Jupiter) — входа нет; отказ по
   монете помнится 5–30 мин, сбой сети — нет.
6. Исполнение: DEMO → виртуально; SHADOW → виртуально по котировке из проверки; REAL → своп по той же котировке →
   подпись → запись подписи в журнал → отправка → подтверждение.
7. Запись в БД + алерт в Telegram + запись в ленту активности. Дальше кулдаун (по умолчанию 300с).

**Журнал REAL-транзакций** (`tx_journal`): подпись известна сразу после подписания и пишется до отправки.
Если ответ RPC потерялся, подтверждение опоздало или процесс упал между отправкой и записью сделки, монитор
каждые 15 с сверяет записи старше 90 с по подписи: поздно исполнившаяся покупка становится сделкой (и
сопровождается), поздно исполнившаяся продажа — выходом, а транзакция, которую сеть не увидела за 3 мин, —
FAILED. Пока покупка «в полёте», монету повторно не покупаем; пока «в полёте» продажа — вторую не отправляем.

### Ручная покупка (экран «Анализ»)

В развёрнутой карточке разбора (и в режиме фокуса, куда открываются монеты из «Избранного») — кнопка
«🛒 Купить вручную»: сумма в USD (по умолчанию 5% баланса), стоп и тейк в %. Покупка идёт тем же путём, что у
бота: живая цена прямо перед покупкой, лимиты портфеля, проверка монеты (authority, Token-2022, маршрут продажи,
влияние на цену), исполнение текущего режима; в REAL — вторым нажатием. Монету с открытой позицией повторно не
купить. Сделка записывается со стратегией «Ручная покупка» и дальше ведётся монитором: стоп, тейк,
ликвидность-стоп (трейлинги и лестницы — от стратегий, у ручной сделки их нет).

### Доска наблюдения (главная, Telegram `/watch`)

Каждый цикл сканера стратегия разбирает кандидата пошагово (импульс → откат → ретест → триггер → объём → стоп…)
и отдаёт, на каком шаге сетап остановился, первое несошедшееся условие с цифрами и уровень, у которого ждёт
входа. Из этого строится доска — без лишних запросов к API: **ГОТОВ** (сетап сложился и прошёл общие фильтры),
**БЛИЗКО** (собрано ≥ 60% и цена в 2% от уровня входа — или сетап есть, но его сняли range-фильтр/уверенность),
**ЖДЁМ** (собрано ≥ 60%), остальные — по «показать все». Строка уходит с доски через 10 минут без обновлений
и сразу после покупки монеты. Шаги: «Пробой на объёме» 8, «Пробой + откат» 9, «Мем-плейбук» 9, Dars 7,
«Эллиотт» — полный список своих проверок, «Вход по баллу» — балл против порога.

### График бота

Открывается кнопкой «📈 График и ведение сделки» на карточке открытой позиции и нажатием на строку доски
наблюдения. Свечи GeckoTerminal обновляются раз в 30 с, ТФ переключается (★ — рабочий ТФ стратегии). Поверх
свечей — как бот ведёт сделку: вход, стоп сейчас и стоп при входе, +1R, безубыток, старт трейлинга (по % или
ATR), частичные фиксации (взятые — приглушённо) и цель; уровни берутся из правил стратегии, выключенное не
рисуется. Ниже — разбор стратегии на рабочем ТФ (сколько условий сошлось, чего не хватает; у «Эллиотта» —
полный список проверок) и пунктир «уровень входа», которого ждёт стратегия. На других ТФ разбор не
показывается: бот решает только по рабочему.

### Выход — TradeMonitor (каждые 15 секунд, работает даже на паузе)

Проверки в порядке приоритета:
1. **Ликвидность-стоп** — пул осушён на X% от входа (дефолт 50%) → экстренный выход (rug pull).
2. **Stop Loss** — жёсткий % от входа (или подтянутый trailing'ом/break-even'ом).
3. **Take Profit** — основной, закрывает всё (в режиме «раннер» — не закрывает).
4. **Partial TP1/TP2** — частичные фиксации долей позиции (в % или R-лестницей — она проверяется до основного TP).
5. **Break-even** — после X% прибыли или после TP1 SL переносится в безубыток+offset.
6. **Trailing** — после активации SL тянется за пиком цены: на фиксированный % или на N × ATR входа (Chandelier), или ступенчато «по иксам» (отступ от пика уже, чем больше иксов взято).
7. **Time-stop** — принудительный выход по времени (если включён; с R-лестницей — только пока TP1 не взят).
8. **Нет нового максимума** — если пик не обновлялся весь срок (по умолчанию 24 ч), остаток закрывается; через 1/6 и 1/2 срока ступенчатый трейлинг сужается на 10 п.п. Время пика хранится в `trade.peak_at`.
9. **Выход по развороту** (тумблер в «🛡 Защите сделок», по умолчанию выключен) — если ничего выше не сработало: на закрытых барах рабочего ТФ стратегии EMA(21) ниже EMA(50), а после входа сложились нижние максимум и минимум (фрактал 3 бара) → остаток продаётся, причина «Разворот рынка». Свечи запрашиваются раз на закрытый бар, через 20 с после его закрытия. В бэктесте 🧪 — тумблер «Выход по развороту» (выход по закрытию бара).

**Выходы по иксам** (секция «🪜 Выходы по иксам», по умолчанию выключены у всех, кроме «Мем-плейбука»): ступенчатый трейлинг и «нет нового максимума».

**Выходы в R** (секция «📐 Выходы в R» в форме стратегии, по умолчанию выключены у всех, кроме «Пробой + откат»):
R — риск сделки, расстояние от входа до *начального* стопа (хранится в `trade.initial_stop`, ATR входа — в `trade.entry_atr_frac`).

Закрытие: REAL → своп token→SOL; SHADOW → по котировке продажи Jupiter; DEMO → виртуально. PnL — в БД, алерт — в Telegram.

**Если продажа не прошла** (нет маршрута, своп упал, RPC отверг): позиция остаётся открытой, в сделке растёт
счётчик неудач (`trade.exit_failures`), а slippage следующей попытки — 3% → 6% → 12% … до потолка из настроек
(по умолчанию 15%). После 3 неудач подряд позиция помечается «🚫 продажа заблокирована»: попытки идут с паузой
1–10 мин, в Telegram — одно предупреждение, на карточке позиции — причина. Если токенов на кошельке нет два
раза подряд (продано вне бота) или при ручном закрытии — позиция закрывается без продажи, PnL неизвестен.

## 7. Установка и запуск

### Требования

- **JDK 17+** (https://adoptium.net). Проверить: `java -version`.
- Исходящий доступ к `api.dexscreener.com`, `api.geckoterminal.com`, `*.jup.ag`, Solana RPC и `api.telegram.org`.

### Windows (самый простой путь)

1. Дабл-клик **`setup.bat`** → заполни `.env` в Блокноте, сохрани.
2. Дабл-клик **`start.bat`** → сервер запущен. Управляй из Telegram.
3. Опц.: **`desktop.bat`** → десктоп-дашборд.

### Терминал (Linux/macOS)

```bash
cp .env.example .env && nano .env   # заполнить
./gradlew :server:run               # сервер (бот)
./gradlew :desktopApp:run           # десктоп UI
./gradlew :androidApp:assembleDebug # APK → androidApp/build/outputs/apk/debug/
```

### Что происходит при старте сервера

1. Открывается SQLite по `DB_PATH`, сеются 3 дефолтные стратегии.
2. Собирается стек: DexClient, кеши, RiskManager, TradeExecutor, StrategyManager, BotEngine.
3. Запускается TradeMonitor (сопровождение позиций).
4. Если задан `TG_BOT_TOKEN` — стартует Telegram long-polling.
5. Поднимается Ktor-сервер на `PORT`.

> ⚠️ **При первом запуске бот НЕ торгует.** Нажми «🟢 Старт» в Telegram/UI или `POST /api/v1/bot/start`.
> Дальше сервер помнит, в каком состоянии бота оставили (`bot.desired_state`), и после рестарта
> (docker `restart: always`, перезагрузка VPS) сам возвращает его в «работает» или «пауза».
> Приложение (десктоп, Android) делает так же только с тумблером «Возобновлять торговлю при запуске
> приложения» в настройках; на Android — и после перезагрузки телефона. На десктопе, который делит
> базу с сервером, тумблер не включайте: на одном счёте торговали бы два бота.

## 11. Риск-менеджмент

Перед каждым входом `RiskManager.canTrade()` проверяет:

1. **Дневной убыток** — если P&L за сегодня хуже `-(balance × maxDailyLoss%)` — вход блокируется до следующего дня.
2. **Максимальная просадка** — худшая закрытая сделка **за последние 24 часа** хуже `-maxDrawdown%` — блокировка. Окно скользящее: через сутки лимит сам отпускает.
   > ⚠️ `maxDrawdown` обязан быть заметно **больше** `stopLossPercent`, иначе штатный выход по стоп-лоссу сам упирается в лимит и глушит стратегию. Дефолт — 30% при SL 15%.
3. **Лимит позиций** — не больше `maxPositions` открытых по стратегии.

Размер позиции: `usdAmount = balance × positionSize / 100` (спот, плеча нет). Баланс из кеша (DEMO-счёт или SOL×цена).

Плюс DEX-специфика: ликвидность-стоп и time-stop на выходе, slippage-лимит в свопах.

### Защита сделок (все стратегии вместе)

Настройки → «🛡 Защита сделок». Лимиты выше — на **одну** стратегию; эти — на весь портфель текущего режима
(DEMO и REAL считаются отдельно). Любой числовой лимит 0 — выключен.

| Настройка | По умолчанию | Что делает |
|-----------|--------------|------------|
| Проверять монету перед покупкой | вкл | `EntryGuard` (§5): authority, Token-2022, котировки Jupiter. |
| Mint/freeze authority отозваны | вкл | Иначе монету могут допечатать или заморозить ваши токены. |
| Отклонять опасный Token-2022 | вкл | Комиссия перевода, перманентный делегат, хук перевода, пауза, непереводимость, замороженные счета. |
| Макс. влияние покупки на цену | 3% | По котировке Jupiter на размер вашего входа. |
| Макс. потери «купить и сразу продать» | 5% | Комиссии пулов и проскальзывание в обе стороны. Маршрут продажи нужен всегда. |
| Открытых позиций всего | 3 | Вместе с REAL-покупками «в полёте». |
| В позициях, % капитала | 50% | Капитал = свободный баланс + позиции по последней цене. |
| Убыток за день / за 7 дней | 10% / 20% | Закрытые сделки + открытые по последней цене монитора. |
| Пауза после N убыточных сделок подряд | 3 сделки → 30 мин | Отсчёт от последнего убытка. |
| Просадка портфеля от пика | 0 (выкл) | От лучшей точки кривой PnL по сделкам (закрытые + открытые по последней цене), % капитала на пике. Пополнение кошелька и цена SOL не считаются. Сама не отпускает. |
| Останавливать бота при лимите убытка | выкл | Лимит за день, за 7 дней или просадки не ставит входы на паузу, а останавливает бота целиком (сообщение в Telegram, запуск — вручную; после рестарта сервер не возобновит). |
| Потолок slippage продажи | 15% | Slippage растёт после каждой неудачной продажи (§5). |
| Выход по развороту рынка | выкл | Продать, не дожидаясь стопа, когда EMA и структура развернулись вниз после входа (§5, п. 9). |

Без ключа Jupiter даёт 0.5 запроса в секунду на все свои API сразу: проверка монеты — 2 котировки на вход,
поэтому отказы по монете запоминаются (5–30 мин), а цена SOL кешируется на 30 с.

## 12. Деплой на сервер (VPS/Linux/Docker)

### Вариант A: Docker (проще всего)

```bash
git clone <репозиторий> drx && cd drx
nano docker-compose.yml   # заполнить TG_BOT_TOKEN, TG_CHAT_ID, SOLTRAD_API_KEY
docker compose up -d --build
docker compose logs -f    # логи
```

БД хранится в `./data/soltradbot.db` (volume).

### Вариант B: systemd

```bash
sudo apt update && sudo apt install -y openjdk-17-jdk git
cd /opt && sudo git clone <репозиторий> drx && cd drx
./gradlew :server:installDist
```

`/etc/systemd/system/drx.service`:

```ini
[Unit]
Description=DRX Trading Bot
After=network.target

[Service]
Type=simple
User=drx
WorkingDirectory=/var/lib/drx
Environment="DEMO_MODE=true"
Environment="TG_BOT_TOKEN=..."
Environment="TG_CHAT_ID=..."
Environment="SOLTRAD_API_KEY=..."
Environment="DB_PATH=/var/lib/drx/soltradbot.db"
ExecStart=/opt/drx/server/build/install/server/bin/server
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -d /var/lib/drx -s /usr/sbin/nologin drx
sudo mkdir -p /var/lib/drx && sudo chown drx:drx /var/lib/drx
sudo systemctl daemon-reload && sudo systemctl enable --now drx
sudo journalctl -u drx -f
```

Не выставляй порт 8080 голым в интернет — прокси через Nginx+HTTPS, если нужен внешний доступ.

## 13. Безопасность

1. **Никогда не коммить `.env` и seed-фразу в Git** — уже в `.gitignore`.
2. **Seed-фраза** хранится локально (env или SQLite). Заведи **отдельный кошелёк для бота** с небольшой суммой — не основной!
3. **Задай свой `SOLTRAD_API_KEY`** (или возьми сгенерированный из лога сервера) — ключ `soltrad-secret` из старых примеров в проде нельзя.
4. **Один `TG_CHAT_ID`** — чужой аккаунт не сможет управлять ботом.
5. **Сначала DEMO, потом REAL.** Минимум 1–2 недели наблюдений.
6. **Мемкоины — экстремально рискованный рынок.** Rug pull, honeypot и осушение ликвидности случаются постоянно; ликвидность-стоп снижает риск, но не убирает его.

## 14. Решение проблем (FAQ)

**Q: `./gradlew` падает с `Could not find Java X`**
A: Установи JDK 17 и пропиши `JAVA_HOME`.

**Q: Telegram-бот молчит**
A: Проверь `TG_BOT_TOKEN`/`TG_CHAT_ID`. Напиши боту `/start` из правильного аккаунта. Убедись, что long-polling не запущен дважды (сервер + desktop с одним токеном конфликтуют — Telegram отдаёт update только одному).

**Q: Бот не отвечает на команды (хотя нотификации приходят)**
A: `TG_CHAT_ID` не совпадает — бот принимает команды только с этого чата, чужие сообщения игнорирует молча. Узнай свой ID через @userinfobot.

**Q: Бот не торгует, хотя нажал Старт**
A: 1) Нет активных стратегий (`/strategies`). 2) Сканер не находит кандидатов — ослабь фильтры (ликвидность/возраст/объём). 3) Риск-лимит достигнут (см. ленту активности). 4) Кулдаун после сделки.

**Q: REAL-режим не включается**
A: Не задана seed-фраза. Настройки → Кошелёк Solana, или `SOLANA_WALLET_SEED` в `.env`.

**Q: Jupiter buy/sell падает**
A: 1) Недостаточно SOL (нужен запас на комиссии ~0.0003+). 2) Публичный RPC перегружен — поставь Helius/QuickNode. 3) Слишком маленькая сумма свопа. 4) Токен без маршрута — Jupiter не может обменять.

**Q: Как добавить свою стратегию?**
A: 1) Класс `MyStrategy : Strategy` в `shared/.../core/strategy/`. 2) Значение в `StrategyType`. 3) Ветка в `StrategyFactory`. 4) Запись в `SeedData.kt` или через UI.

**Q: Как использовать одну БД для сервера и десктопа?**
A: Одинаковый `DB_PATH`. Но **не запускай два движка одновременно** — будут дубли сделок.

**Q: Где история сделок?**
A: Таблица `trade`; в UI — вкладки История/Аналитика; в Telegram — `/stats`, `/report`.
